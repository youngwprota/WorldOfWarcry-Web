# Автобалансер: цели → подобранные числа
Ветка: feat/balance-tuner (от feat/balance-sync) · Статус: утверждён

## Цель
В balance.html (вкладка «Цели») или в `npm run tune` выставляешь: минуту падения каждого из 7 боссов, длину боя с ним,
длину боя с мобом / элиткой / мини каждой локации, долю мощи от гача-предметов. Тулза подбирает числа конфига,
показывает «было → стало» и записывает их в `src/config.ts` отдельным коммитом.

## Решения
- Менять можно всё (ответ): врагов, награды, тир зон, крутки, гача-предметы, оружие и броню. Оружие и броню —
  только общим множителем группы, чтобы не сломать соотношения со стенда (допущение).
- «Сила» = общая мощь (ответ): `might` из simcore (урон в секунду × живучесть). Доля гачи = 1 − мощь без
  гача-предметов / мощь с ними, в момент первого убийства босса.
- Запись: блок между маркерами `// <tuned>` … `// </tuned>` в конце src/config.ts — присваивания вида
  `MOBS.elf_queen.hp = 21400;`. Игра и сим подхватывают сами, откат — удалить блок; коммит отдельный (ответ).
- Подбор по локациям по цепочке: лес → кладбище → Перевал → Холмы → Роща → Болото → Дюны. Локация подобрана —
  её числа зафиксированы, сим сохраняет состояние героя на её боссе, следующая считается с этого чекпойнта.
- В локации: HP мобов по рангам и босса — напрямую (длина боя × урон героя в секунду к нужной минуте);
  урон босса — бисекцией до шанса победы ≈ 50% в целевую минуту; темп (минута босса) — бисекцией множителя
  наград мобов локации; доля гачи — бисекцией `GACHA.token` по рангам и множителя бонусов GACHA_GEAR.
- Допуск по умолчанию ±10%; цель вне допуска после N итераций — в отчёте красным, что не сошлось и почему.
- Цели по умолчанию — `src/tunetargets.ts` (типизированный объект), страница хранит свои в localStorage
  и умеет экспорт/импорт JSON; CLI берёт `--targets file.json` или умолчания (допущение).
- Запись из страницы — dev-only POST в мидлвари vite.config.ts (на Pages кнопки нет), из CLI — `--write`.
- Скорость: чекпойнты + CLI гоняет прогоны в worker_threads; без этого подбор всех 7 локаций — часы.

## Файлы
- новые: src/tuner.ts (подбор, без DOM/node), src/tunetargets.ts, tools/tune.ts, src/tunetab.ts (вкладка «Цели»)
- меняем: src/simcore.ts (чекпойнты, метрики: доля гачи, бои по рангам, учёт гача-предметов), src/balancepage.ts,
  src/balanceworker.ts (задание tune), vite.config.ts (мидлварь записи), package.json (скрипт tune), README.md

## Шаги
- [x] 1. simcore: метрики — у каждого босса минута, длина боя, доля гачи в мощи; длина боёв по рангам и локациям;
  гача-предметы помечены. CLI печатает их рядом с целями из tunetargets.ts.
- [ ] 2. simcore: чекпойнт — `simulate({ from })` продолжает прогоны с сохранённого состояния (герой, юниты, ворота, t).
- [ ] 3. tools/sim.ts и tools/tune.ts гоняют прогоны в worker_threads; замер до/после в handoff.
- [ ] 4. src/tuner.ts: подбор одной локации (HP по рангам, босс: HP и урон, темп наградами, гача) по чекпойнту;
  `npm run tune -- --zone forest` печатает правки и итог против целей.
- [ ] 5. tuner: вся цепочка 7 локаций, отчёт «было → стало», `--write` переписывает блок `<tuned>` в config.ts.
- [ ] 6. balance.html: вкладка «Цели» — форма целей, запуск подбора в воркерах с прогрессом, таблица «цель / было / стало»,
  графики до и после, кнопка «Записать в config.ts» (dev).
- [ ] 7. README, `npm run build`, полный подбор с целями по умолчанию, проверка в браузере.

## Проверка
- `npm run build` без ошибок
- `npm run tune -- --zone forest`: Атаман в пределах ±10% от цели, длины боёв в допуске
- полный `npm run tune -- --write` → блок `<tuned>` в config.ts, повторный `npm run sim` даёт цели в допуске
- в браузере: «Цели» → поменять минуту Королевы → «Подобрать» → таблица сходится → «Записать» → файл изменился;
  игра (index.html) запускается с подобранными числами
