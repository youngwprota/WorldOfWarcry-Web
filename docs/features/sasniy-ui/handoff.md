## Решения по ходу
- Шрифт: @fontsource/rubik 600/700/900 импортируется в main.ts. Обводка текста — переменные --stroke / --stroke-s (text-shadow), а не -webkit-text-stroke: тот съедает тонкие буквы.
- Кнопки .btn: цвет через --c1/--c2, варианты primary/red/purple/green/blue. Отдельная красная .xbtn для ✕. fmtK() лежит в icons.ts.
- Иконки: icon(id, color, size, cls) в icons.ts. ARMOR_SLOTS.icon теперь id иконки ('head'…), а не эмодзи. cellHtml() и itemIconId() лежат в items.ts (items импортирует icons, обратного импорта нет). Цвет редкости ячейки задают классы .r0–.r3.
- HUD: нижняя полоса #equipbar = #weapons (2 оружия, тап по неактивному = смена) + #armorbar (6 слотов брони, тап открывает окно героя через ui.onArmor). ui.weapons() теперь принимает и equip. Кнопки Герой/Сумка — #side-btns справа над полосой.
- Виджет босса: HudState.bosses {name, left} (left — целые секунды, поэтому ключ JSON меняется раз в секунду). Тап по виджету открывает карту.
- Сумка: .sheet (нижняя шторка, #modal:has(.sheet) прижимает её к низу). Фильтр bagFilter all/weapon/armor. Ячейки в сумке без пустых слотов, вместимость показана в строке вкладок.
- Карточка предмета: #i-tip — это .tip-wrap на уровне #modal (затемняет всё, тап мимо карточки закрывает её), внутри .tip. Кнопка ✕ = data-act=close. Способность оружия — добивание из COMBOS.
- Окно героя тоже .sheet: карточка «Характеристики» (DPS = урон за удар × powerMult × aps, HP, реген в HP/с) + 6 чипов, кукла, полоса сумки, кнопка «Открыть сумку». Кузнец = .panel.shop с лентой и карточками; цена кнопкой с монетой.

- Иконки: цветные art(id, size, cls) в src/art.ts (сетка 64×64, P = с обводкой, N = тень/детали, H = блик). Плоские icon() остались для значков резиста над мобами, значка типа урона в углу ячейки и пустых слотов. ART.bag — сундук, regen — зелёное сердце с плюсом.
- «Характеристики» вынесены наверх экрана (.top-stats) над шторкой и в сумке, и в окне героя: Inventory.statsPanel()/renderStats(). #modal:has(.sheet) — колонка: панель сверху, шторка снизу.
- Обводка текста толще (--stroke 2.6px, --stroke-s 1.7px), рамки кнопок и ячеек 4px.

- Скин «дерево и глянец» (блок в конце style.css): --grain (SVG feTurbulence, data URI), --planks (стыки досок), --bolts / --bolts-top (болты по углам), --gloss (блик на кнопках и ячейках). Применено к панелям, шторке, карточке, плашкам, вкладкам, полосам «Экипировано».

- Мультяшный проход («cartoon pass» в конце style.css), по замечанию пользователя «слишком реалистично, мелко»: текстуру из шума заменили плоские SVG-доски (толстые стыки, светлая кромка, редкие штрихи волокон). Кнопки и ячейки — плоские в два тона (--c1 сверху, --c2 снизу) вместо градиентов. Рамки 5px, обводка текста 3.6px (--stroke) и 2.4px (--stroke-s), обводка иконок art 5.5 на сетке 64. Шрифты ещё крупнее. Направление для дальнейших правок: толсто, плоско, крупно; без реализма.

## Грабли и что не сработало
- Деревянная текстура из feTurbulence выглядела слишком реалистично для мобильного мультяшного стиля, её отклонили.
- Переменная с несколькими слоями фона (--bolts = 4 слоя, --bolts-top = 2) сдвигает список background-size. Без явных размеров и no-repeat болты расползались по всей шторке.
- Первый вариант был слишком мелким для телефона (замечание пользователя). Блок «mobile sizing» в конце style.css укрупняет всё под пропорции референса при ширине ~390px: миникарта 140, кнопки сбоку 76, полоса снизу — 8 равных слотов, .btn 60px, стик радиусом 16% экрана. Новые размеры менять там.
- bash heredoc с python-кодом, где много кавычек и скобок, ломался (unexpected EOF). Большие правки лучше писать скриптом в scratchpad и запускать файлом.
- Скриншоты в Chrome: окно браузера широкое, приложение рисуется колонкой 9:16 по центру; resize_window на скриншот не влияет.
