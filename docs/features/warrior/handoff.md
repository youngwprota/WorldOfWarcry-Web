## Решения по ходу
- Гача по-прежнему берёт Object.keys(WEAPONS): после удаления там только оружие воина и щиты — отдельный список не нужен.
- polearm: dmgMul 0.9, aps 1.0 (0.8 было слишком слабо: стенд 153 с против 96 у меча, теперь 115), range 3.1, single+cycle, свинги thrust/thrust/slashRL, COMBOS.polearm «Прокрут» круг ×1.4 со spin. Ключ rig.ts остаётся `nagamaki` (это имя модели).
- Щиты: dmgMul 0 и без COMBOS (код читает COMBOS[...]?. / пропускает guard). Ответ щита — Game.shieldAnswer: щит всегда в слоте 1, оружие в слоте 0; отражение через damageMob без отброса.
- party.ts: kitOf(c) (пустой список → набор воина), classSlot(c, def) → 0|1|null; в items.ts уже был slotOf (броня), поэтому другое имя.
- Переименования defs в normalizeItem (RENAMED: nagamaki→polearm, shield→shield_tower), раскладка по слотам в loadSave.
- Кнопки «В правую/В левую» заменены одной «Экипировать» (ее часть сделана уже в шаге 5, шаг 6 — README).
- Камерный zoom в slowMo оставлен (сейчас никто не зовёт с zoom>0).
- Пользователь выбрал: экзотику и пары с мечом удалить совсем; 3 щита с разной ролью; древковое = переделанная нагамаки.
- Модели по качеству: оружие `<тип>_<качество>` и щиты `shield_<вид>_<качество>` — GLB из wow.blend (tools/blender/rarity_gear.py), common оружия = старые FBX (itemModel в items.ts). Щит лицом в +Z glTF, верх +Y, рукоять в начале координат, см.
- Хват щита — attachShield: рукоять щита (SHIELD_GRIP.handle) в ладони, щит сдвинут наружу на 9 см (кулак мультяшный, иначе торчит сквозь щит), лицо → кисть +Y, верх наклонён от предплечья к оси кулака (lean 0.6). Подбирать в viewer.html: window.SHIELD_GRIP + attachWeapon.
- Мифическое древковое у художника — коса (лезвие вбок), так и оставлено.
- Анимации древкового: укол и финишер `sweep` (src/swing.ts) подобраны по углу древка к горизонту (в кулаке оно стоит ~30° вверх, рука вверх = древко вертикально): на ударе и весь прокрут 2–6°. Проверять в viewer.html?solo=12: в списке «swing: …», window.pause/step/KEYS.
- Броня по качествам: tools/blender/armor_gear.py (импортирует rarity_gear) строит детали в mesh-пространстве персонажей (см, Y вверх, лицо +Z — совпадает с геометрией в игре, bindMatrix = I), узлы `<glb>__<кость>`; в игре attachTrim (rig.ts) вешает узел на кость с boneInverse. Подгонка по мешам каждого комплекта (3 × 2 фракции), кольцо/амулет — по фракции. 144 GLB, ~4,7 МБ, грузятся лениво (assets.gear, Character.setTrims). Материалы armor_body (Lambert, цвет вершин) и armor_glow (Basic — «светится»).
- Наплечники на clavicle_*, не upperarm: в bind T-позе руки горизонтальны, при опущенной руке накладка на плечевой кости уходила вбок.
- Кости для подгонки берутся у peasant: скелет у всех общий, но у части моделей кисти названы Character1_*.

## Грабли и что не сработало
- Подмена сейва в localStorage из консоли: игра перезаписывает сейв при выгрузке — перед reload нужно глушить Storage.prototype.setItem.
- Подсказка в настройках про смену оружия (Q / тап) была устаревшей — заменена на смену класса.
- `npm run sim` и до ветки (на e4a623f) выдаёт 0 убийств боссов — сломан ещё слиянием карты, не наша регрессия. `--bench` работает.
- Качество щита пока ни на что не влияет (guard плоский) — вынести в баланс.
- Финишер древкового был slashRL (рука поднята вперёд) + прокрут тела с момента удара → древко торчало вверх во время прокрута.
- Экспорт: материал общий для нескольких объектов переименовывался на каждом (имена росли `__src__src…`) — теперь одна белая копия на материал. Экспортёр пишет «render»-цвет в COLOR_0 (белый, если не задан) — нужно render_color_index = active.
- Сохранять поверх Downloads/wow.blend из Blender нельзя: создаст бэкап wow.blend1 поверх оригинала пользователя — сохранять в scratchpad и копировать.
- Топоры (FBX и GLB) держались лезвием назад-вверх (roll π): roll подобран замером в viewer — лезвие вперёд-вниз при опущенной руке (axe/peon −0.86, grunt −0.92, chieftain −0.62).
- Палитра в rarity_gear.py задаётся в sRGB и переводится в линейный (lin): иначе в игре щиты белёсые.
- Лицо щита в −Z кисти смотрело назад («криво держит»); правильно — +Y.
- Оружие из blend было белым в игре: у художника клинок красит вершинный цвет Col (экспорт клал его в COLOR_1, three читает COLOR_0), рукояти — текстура персонажа × Mix-оттенок (картинки не экспортируем). Теперь bake_colors в rarity_gear.py запекает итоговый цвет в один атрибут, материалы белые. Нормали при экспорте пересчитываются наружу (часть граней была вывернута).
- src/helpers.ts (помощники молот+серп) удалён вместе с парами; Falls в orbits.ts остался без пользователей.

- Слияние origin/main (охотник + маг) в warrior: броня по качествам (armorTrim, Game.trims) — только для класса warrior; inventory.setGear получил orb и trims.
