# Фиксация статов в автобалансере
Ветка: feat/tuner-locks · Статус: утверждён

## Цель
Во вкладке «Цели» (balance.html) раскрыть список статов, которые трогает подбор, и у каждого снять/поставить галку
«авто». Снятая галка — поле для ручного значения, подбор это число не меняет. config.ts помнит, какие числа ручные.
Плюс цель «потеря HP за бой, %» по рангам и локациям: бои «на грани», а минута босса — всё равно как задано.

## Решения
- Статы подбора — `TUNE_KNOBS` в src/tuner.ts: по локации `ZONE_SCALE.<z>.hp|dmg.<ранг>`, `ZONE_SCALE.<z>.token`,
  `MOBS.<босс>.hp|dmg`; общие `GACHA.token.<ранг>`. Список и для UI, и для CLI — один.
- Ручной признак в конфиге: `export const TUNE_MANUAL: string[] = []` перед блоком `// <tuned>`, ручная строка блока —
  `MOBS.death.hp = 9000; TUNE_MANUAL.push('MOBS.death.hp');`. Это код, а не комментарий — игра/страница/CLI читают
  признак импортом, без разбора текста. Авто-строки — как сейчас.
- `writeTuned(src, sets, manual)`: `manual` — полный список ручных (путь → число): их строки пишутся с меткой,
  у остальных метка снимается (галку вернули — число остаётся, но снова авто).
- Тюнер: `TuneOpts.fixed: Record<path, number>` — применяются до подбора (в job.sets перед подобранными), `set()`
  их пропускает: HP/урон мобов ранга, HP босса, бисекция урона, шанс круток, заполнение GACHA.token. Остальное — как было.
  `TuneOut.fixed` — чтобы итог показал их отдельно («вручную»), а запись не потеряла.
- UI: под таблицей целей `<details>` «Статы подбора» — секции по локациям + «Общие»; строка: имя, галка «авто»,
  при снятой — поле числа (подставлено текущее значение). По умолчанию: ручные = `TUNE_MANUAL` со значениями
  из конфига, остальные с галкой. Состояние — localStorage `warcry-balance-locks`; кнопка «Как в конфиге» сбрасывает. (допущение)
- Запись: «Записать в config.ts» шлёт `{ sets, manual }`; в панели статов своя кнопка «Записать ручные в config.ts»
  (без подбора, `sets` пустой) — только в dev. (допущение)
- Потеря HP = taken / maxHp победного боя (пачка — один бой), медиана; цель `TuneTargets.loss` (доля 0…1, в UI — %),
  допуск в пунктах, как у гачи. Ручка — `ZONE_SCALE.<z>.dmg.<ранг>` × (цель/факт)^0.7 в шаге мобов. Минуту держит
  прежний подгон босса под героя целевой минуты — `reward` не трогаем (две ручки на одну цель). Умолчания: моб 50%,
  элитка 70%, мини 85% (допущение). Старый JSON целей без `loss` — урон мобов не подбирается.
- CLI: `npm run tune` берёт ручные из `TUNE_MANUAL`, `--write` их сохраняет. Флага для ручных нет. (допущение)

## Проверка
- `npm run build` без ошибок
- в браузере (npm run dev, /balance.html → «Цели»): раскрыть «Статы подбора» — все галки стоят, числа из конфига;
  снять галку у `MOBS.bandit_chief.hp`, ввести 3000, «Подобрать» только лес (1 круг, 2 прогона) — в итоге hp босса
  не меняется, строка помечена «вручную»; «Записать в config.ts» — в блоке строка с `TUNE_MANUAL.push`, после
  перезагрузки галка снята и стоит 3000; вернуть галку и записать — метка ушла, число осталось.
- `npm run tune -- --zone forest --runs 2 --iters 1` — ручное число не меняется; потеря HP мобов леса тянется к цели.
