# Фикс: мир становится тёмным на телефоне (утечка WebGL-контекстов)
Ветка: fix/webgl-contexts · Статус: готово к проверке

## Цель
После нескольких открытий инвентаря/Горнила 3D-мир на телефоне пропадает: остаётся тёмно-синий
фон (--bg #1b1a24), а HUD, метки мобов и миникарта на месте. Мир должен рисоваться всегда.

## Диагноз
- Это не тёмная тема: на скриншоте HUD не выцветший, значит фикс color-scheme (fix/friend-phone) работает.
- Пустой фон = основной WebGL-контекст потерян. Миникарта — 2D-картинка, её это не задевает.
- inventory.ts:169 создаёт `new HeroPreview` → новый WebGLRenderer на каждое открытие инвентаря,
  forge3d.ts:139 — то же для Горнила. `dispose()` не освобождает контекст (нужен forceContextLoss),
  контексты копятся до GC. Chrome держит ~16 контекстов на ПК и меньше на Android, затем
  теряет самый старый — это главный рендерер игры. three.js останавливает setAnimationLoop,
  и мир не возвращается.

## Решения
- В dispose() HeroPreview и Forge3D звать `renderer.forceContextLoss()` после `dispose()` —
  контекст освобождается сразу, одновременно живут максимум 2. Минимальная правка.
- Страховка в main.ts: слушать `webglcontextlost` / `webglcontextrestored` на canvas игры.
  three.js сам делает preventDefault и перезапускает цикл при restore. Если restore не пришёл
  за 3 с — `game.persist()` и `location.reload()` (допущение: перезагрузка лучше чёрного экрана).
- Общий переиспользуемый рендерер для превью не делаем — больше правок, тот же эффект.

## Проверка
- tsc без ошибок, `npm run build` собирается
- ПК: 30 раз открыть/закрыть инвентарь и Горнило — нет «Too many active WebGL contexts», мир виден.
- ПК: в консоли `__game()` + `renderer.getContext().getExtension('WEBGL_lose_context').loseContext()`
  (или через debug-панель) — через 3 с страница перезагружается с сохранением.
- Телефон: долго играть, часто открывать инвентарь и ковку — мир не пропадает.
