## Решения по ходу
- Новые id: gloves_power/crit/haste, ring_shadow/blood, amulet_heart/ward (`GACHA_GEAR` в items.ts). Любой `*_arms` в сейве → gloves_power.
- `haste`/`leech` — кривые в STAT_CURVE; haste множит aps всех рук (heroDps тоже), leech — `Game.leech()` в damageMob и burnMob.

- Питомец = запись WEAPONS[<id из PETS>] с полем `pet` (генерится из PETS в config; после слияния с main id предмета = id зверя, вепрь — `boar` как в main), kind 'weapon', лежит в weapons[1] охотника (CLASSES.hunter.off). Не новый ItemKind — так сумка/копии/гача работают без правок. `petCellHtml` удалён.
- Сейв: `givePet` из main (пустой слот охотника → его kit.left = `boar`); `pet_<зверь>` из сейвов ветки → `<зверь>` в normalizeItem. Урон — модель main: свой урон предмета (`weaponDamage(it)` = PETS.dmg как dmgMul × качество, копии, заточка), без силы героя и лука; наше сверху: haste, прыжок ×mult, удар лапой. PET_RARITY теперь только размер.
- Иконки питомцев: public/assets/ui/pet_<id>.png в стиле main — `tools/blender/pet_portrait.py <glb> <png> 35 1 10`, потом icon_shrink.py (вепрь из main, остальные 4 перерендерены так же).
- Pounce: прыжок дугой LEAP_TIME 0.4 с (pet.ts), укус при приземлении ×mult, показан жёлтым как крит. Cleave: укус по всем дерущимся мобам в `cleave` м от цели (game.ts updatePet). Анимации зверей — те же клипы, что у мобов-зверей.
- Значок стата на ячейке — только для GACHA_GEAR (`BONUS_ICON` в items.ts); у сфер убран значок типа урона. Щиты — только шипастый, как в main: `shield`, `shield_tower`, `shield_buckler` в сейве → `shield_spiked`.
- Гача: `poolItem` в gacha.ts — слот 1/4 каждый (перчатки/кольцо/амулет/предмет класса), класс случайный; сферы по `GACHA.orbs[tier]`. Баннер `GACHA.banner` теперь с `kind`.
- Sim: leech и pounce смоделированы, cleave нет (бои один на один). Сим совпал с main (Атаман 40:30) — крутки с мобов выключены, гача на сим не влияет.
- Проверено в node: 3000 круток — только гача-предметы, сферы по своим тирам, баннер ровно раз в ≤60; старый сейв (pet, plate_arms, hunter_arms, щит-баклер) грузится: pet_boar в слоте, перчатки → gloves_power.
- Прогон в браузере: миграция сейва, 5 круток (гарант → Кольцо Короля-лича), питомец из наковальни (масштаб по наибольшей стороне, FORGE3D.petSize), прыжок льва ×2,5, лапа медведя по 2 мобам, перчатки воина/охотника/мага разные, значки статов, карточка питомца. «Защита 0» у колец скрыта.
- Горнило: у всего, что выпадает, своя модель. Кольцо/амулет — GLB `armor_<slot>_<качество>_<фракция>` (грузится `assets.gear`), перчатки — меши `arms_` части комплекта класса на поле, запечённые в bind-позе, одна рука (`oneArm`), сферы — через cloneCreature. Модели грузятся в `Forge3D.prepare` до начала сцены. Размер по наибольшей стороне: FORGE3D.gearSize / petSize.
- Кольца и амулеты больше не надеваются на модель героя (просьба: «их не надо на персонажа»). Витринные модели `jewel_<slot>_<качество>` строит tools/blender/jewels.py (без фракции, свои PBR-материалы, 8–35 тыс. треугольников — только для Горнила), `assets.jewel()` грузит их без перевода в Lambert. Иконки `armor/<slot>_<качество>.png`: icon_render.py с новыми аргументами pitch и `studio` (кольца `1.1 0 0 25 50 studio`, амулеты `1.1 0 0 15 10 studio`), потом icon_shrink.py. Старые armor_ring/amulet_* GLB и фракционные PNG удалены, из armor_gear.py убраны.
- Горнило для украшений: RoomEnvironment-PMREM в envMap, светятся только камни `jewel_gem_*`, bloom ослаблен до `FORGE3D.jewel.bloom` (иначе золото выжигается в белое), свет предмета `jewel.light`, металл темнее на `jewel.metal`. Блики (`sparkle`) — на случайных вершинах, рой (`addMotes`) — орбиты на GPU, без работы на CPU в кадре. Украшения качаются (`swing`), а не крутятся: у медальона гладкая спина.

- Баннер: `Showcase3D` (src/showcase3d.ts) — своё WebGL, фон-шейдер (лучи `BANNER3D.ray`, звёзды), круг-руны, украшение через общий `JewelFx` (src/jewelfx.ts, его же использует Горнило). Один контекст за раз: витрина убивается перед ковкой и создаётся заново на возврате к баннеру. Размеры модалки в «дизайнерских» px (--ms ≈ 0.5 масштаб): `dvh` в ней не работает, баннер тянется `flex: 1 1 0`.
- Сферы мага: `magicOrb` (src/orbfx.ts) меняет стеклянную оболочку (меш с именем модели) на шейдер-туманность с ободком, добавляет рой точек (`ORB_FX[model].mode`: 0 кружат, 1 поднимаются, 2 скользят по сфере) и ореол-спрайт. Время и масштаб точек — в onBeforeRender, поэтому работает в любом рендерере (поле, окно героя, Горнило). В Горниле навешивать после замера рамки, иначе ореол уменьшает сферу. Иконки сфер `public/assets/ui/orb_*.png` рендерятся этим же шейдером: tools/orbicons.html (в dev, время заморожено `?t=`), потом tools/blender/orb_icon_post.py (обводка без мелких искр, 128 px).
- Лев (просьба «улучши модель льва», выбран вариант «доработать WoW-модель»): tools/blender/lion_upgrade.py берёт нетронутый Art/Source/wild_lion_base.glb и добавляет меш `lion_fur` (пучки с вершинным цветом: тёмная грива с медными кончиками, золотые бакенбарды, борода, грудь, локти, кисть хвоста). Вес каждого пучка — копия весов ближайшей вершины тела к его корню (`anchor`), поэтому мех идёт за всеми 4 клипами. Первая версия была 21 тыс. граней — урезана до ~2,7 тыс. (4 стороны, 3 кольца, меньше пучков, шире). Иконка pet_lion перерендерена (icon_render + icon_fit — это blender-скрипт, не python).
- Перчатки (просьба «улучши модели перчаток»): витринные модели `gloves_<вид>_<качество>` (tools/blender/gloves.py, хелперы импортирует из jewels.py — там `main()` под `__name__` guard), 9–34 тыс. треугольников, материалы `jewel_metal/gem/diamond_<r>` как у украшений → `JewelFx.dress` работает. `items.showcaseModel(item)` заменил `jewelModel`: кольца/амулеты/перчатки; Горнило даёт им всю «ювелирную» подачу. `oneArm` и выбор по классу в Горниле удалены (`prepare(item)` без класса). На герое перчатки по-прежнему из комплекта класса — витрина только в Горниле и иконках (`armor/gloves_*`, icon_render `1.1 0 20 0 10 studio`). Старые иконки `*_arms_*` остались в ui/armor, гача их больше не использует.

- Слияние origin/main (11 коммитов: ружьё, древковое у охотника, питомец-предмет, стартовые наборы, мобы, карта): воин — оружие, kit и щит из main (только шипастый — так решил пользователь после слияния). icon_render.py: аргументы 5–6 — spin/tilt из main (при roll 0 то же, что наши yaw/pitch), 7-й — `studio`. Предпросмотр героя — newPreview из main, пересоздаётся и при смене питомца/его качества (petKey). Сим совпал с чистым origin/main (Атаман 35:09, Смерть 43:02).
## Грабли и что не сработало
- Утечка рендер-цикла: Showcase3D/Forge3D запускают loop после асинхронной загрузки — если окно закрыли раньше, цикл крутился вечно (rAF ×2 после быстрого открыть-закрыть). Теперь флаг `dead` в dispose. Проверка: обёртка rAF + счётчик drawElements по canvas через CDP — после закрытия Горнила должно быть как до открытия.
- Vite после серии HMR правок CSS начал отдавать style.css пустым; TaskStop не убил node — старый сервер держал 5173. Лечится taskkill по PID с порта и перезапуском.
- Сферы мага тоже лежат в `creatures`, поэтому в Горниле были ромбом, как броня.
- Тест: при открытом Горниле игра на паузе, и `switchClass` упирается в SWITCH_COOLDOWN (время не идёт).
- Питомцы в WEAPONS попали в предзагрузку FBX (main.ts) → загрузка висла на 97% («FBXLoader: Unknown format»). Исключены вместе со сферами.
- Проверка без расширения Chrome: headless chrome.exe с --remote-debugging-port=9222 + свой CDP-клиент на WebSocket из node; в dev `window.game` (main.ts). Headless рендерит медленно: ~1 с игры за 7 с реальных.
- icon_render.py берёт рамку по вершинам без скиннинга — у зверей картинка уезжала вверх; добавлен REST-pose и обрезка/центровка в icon_fit.py.
- Звери не в `assets.sources`, а в `creatures`: `assets.has()` для них false → добавлен `hasCreature`, клон через `cloneCreature`.
